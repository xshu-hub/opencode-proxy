# Magpie 对照审查与整改范围

**历史记录（已被 0.7.0 范围变更取代）：** 当前仅保留模型与网关，统计与请求记录已移除；前端同步到 Magpie a75de4c2。以下旧计划不再作为当前开发任务，现状见 [frontend-port.md](frontend-port.md)。

审查日期：2026-10-13。参考本地 Magpie 提交 `210234a5f33e0f2643f82b4337e249cf0fe81371`；独立工具发布基线为 0.4.0 的 `54bd040e73ae1655a859b1b5f77a4a177c9a1126`。

## 结论

0.4.0 复用了 Magpie 的完整基础 CSS、顶部/列表/账本 HTML 结构和少量 DOM 控件，但不是完整页面逻辑的移植。Magpie 的供应商、路由、用量、请求、设置数据接口未移植；独立工具的简化 renderer 与后端只实现了其中一部分。因此“有 Magpie 样式”不能等同于“具有 Magpie 功能”。

思考配置要求用户填写 SDK JSON 是错误的产品交互。正常界面应选择档位；模型使用预算时才显示 Token 数值输入。SDK 参数在后端生成，不要求用户理解 SDK。

## 功能对照

| 功能 | Magpie 来源 | 0.4.0 状态 / 缺项 | 独立工具应保留的行为 |
| --- | --- | --- | --- |
| 思考强度 | `internal/gui/assets/app.js` 的 `effortSeg`、`renderEffortPicker` | 原生滑块存在，自定义通过 JSON，保存后关闭滑块，交互不完整 | 档位选择、可选档位配置、预算输入、原生默认说明；键盘操作与连续选择；程序生成映射 |
| 供应商与模型 | Providers 页、`internal/provider`、`providers-accounts.md` | 只有按 provider ID 分组的模型，没有供应商状态页、来源说明、诊断入口 | 展示 OpenCode 已连接供应商、所属模型、能力、启用状态、发现错误与刷新；登录仍由 OpenCode 管理 |
| 网关连接 | `renderGateway`、`FLAVORS`、`connect` | 只有基址和三协议名称、单次非流式测试 | 三协议实际 URL、SDK/cURL 配置示例、客户端连接说明、真实流式测试、停止/启动状态 |
| 模型管理 | `gatewayModels`、`renderGatewayModels`、模型 picker | 启停、别名、基础参数存在；无收藏、排序偏好、能力筛选、批量参数、价格说明 | 保留来源与默认/覆盖区分、批量选择、收藏、能力筛选、复制 ID、可验证的上下文/输出与原生能力 |
| Key 管理 | `internal/access/access.go` 的 `Key` | 只有名称、Key 值、启停；没有模型范围、预算与按 Key 累计用量 | 每客户端独立 Key、模型权限、累计统计；预算与配额按后端可验证数据实现，不能只加表单 |
| 路由 | Routing 页、`gateway-routing.md` | 一对一别名，没有路由组、候选顺序、失败切换、路由轨迹 | 同一别名的多候选 OpenCode 模型、明确策略、首输出前失败切换；已经输出后不得悄悄重试拼接回答 |
| 用量 | `renderUsage`、period、`usageModels`/`usageKeys`、`renderLedgerDash` | 累计模型统计、90 天日总量存在；没有按 Key、供应商、期间分组和费用；部分速度公式复用 | 时间范围 + 模型/供应商/Key 维度、趋势、缓存/思考拆分、原生费用或明确缺失；所有聚合口径须一致 |

| 统计口径 | Usage 页的 `usageScope`、`ledScope` | 速度、首字有效样本规则复用；本地模型停用、参数错误仍计入 totals | 日志保留本地拒绝，但供应商调用总量不计入本地拒绝。旧历史无法凭剩余 250 条准确重算，应注明版本边界 |

## 本轮已落地的交互修正

- 模型表单改为中文档位按钮选择，不显示 JSON 编辑器。
- 自定义档位使用勾选；原生 Anthropic SDK 的预算使用整数输入，后端校验至少 1024 且小于输出上限。
- 后端自动根据 OpenCode 报告的 SDK 类型选择可实现的配置方式；未知 SDK 保留原生配置，避免猜测预算语义。
- 原生默认、客户端覆盖、自定义可选档位的优先关系保留。旧 JSON 映射仍可读取和保留，常见档位映射自动转换为选择界面。
- 模型保存错误放在模态框内部，编辑内容不会丢失。
- 启动附加参数改为可增删的逐行文本输入，不要求填写数组 JSON。

这些修正不代表上表的其余缺项已经实现。

## 整改顺序与验收

1. **模型与基础交互**：选择式思考配置、供应商状态/来源、模型能力与批量操作、分区设置。无必填 SDK JSON；刷新不覆盖编辑；档位与实际推理参数一致。
2. **日志与统计**：先修本地拒绝口径，再扩展按天持久化的维度数据；增加范围/Key/供应商筛选、导出、完整文件查看和保留策略。不得拿最近 250 条冒充累计统计。
3. **Key 与路由**：后端先实现所有协议上的权限校验和模型列表过滤，再接页面；候选切换必须记录每次尝试，流式开始后不隐式重试。
4. **运行与设置**：托盘恢复/退出、自启动、网络设置、备份、版本诊断。优先通过服务 + 浏览器验证页面，Windows 特有生命周期另测。
5. **兼容能力**：逐项核对原生三协议的参数、工具语义与事件，不以 UI 完整掩盖底层缺项。

Magpie 的 Agents、Sessions、Library、Plugins 有独立的代理配置写入、会话扫描、技能/MCP 安装等职责。它们不应被机械复制成假页面：本工具的既定职责是由真实 OpenCode 发起推理，客户端执行外部工具，全局登录和认证插件由 OpenCode 管理。

订阅剩余额度、账户轮换、供应商登录写入也需要 OpenCode 或插件提供真实数据接口。仅凭 `/provider` 的 connected 列表无法得到每个订阅的剩余额度，不能生成仿真数字来补齐页面。
