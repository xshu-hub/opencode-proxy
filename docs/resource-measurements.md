# Session 管线资源测量

日期：2026-11-02。环境：Windows x64，Node.js 22.23.2，真实 OpenCode 1.16.2 / 1.18.0。

比较基线为 `584b9693a8b62efabce3a87c40d2413682019e6d`（0.12.0）；优化实现为 0.13.0。两侧使用同一测量脚本、临时配置、模拟供应商和负载，真实 OpenCode 程序不作修改。

## 机制与边界

- 全局模式默认共享常驻进程。相同运行配置与工具合约下，模型和供应商不额外拆分进程；每次推理仍指定自己的模型。
- 每个共享进程只维护一条 `/global/event` SSE，按目录和 Session ID 分发；每请求独立队列上限为 8 MiB，取消或结束立即释放订阅及队列。
- 纯文本合约不建立空 MCP 服务；客户端工具和需要捕获的结构化输出仍使用 MCP。
- 刷新模型会创建新的配置代次；旧代次等待活动请求完成后退出，避免重复使用旧 provider 配置或凭证。
- 工具 schema、权限或运行配置不同仍需分组。显式配置 `workerSharing: false` 仍使用独占模式。默认并发不设上限。
- 全部推理仍通过官方 Session、SDK 与最终 provider 发送链；保留认证插件、请求头和针对实际 SDK 请求体的签名。

## 测量方法

每个场景均从新的桥接实例开始。模型发现完成后开始计时，包含推理进程启动、完整流式输出和请求清理，不包含最终进程退出。

模拟上游使用屏障，等所有请求到达后再返回流。每请求输出 160 段文本；逐条核对最终拼接结果、请求标记、供应商凭证和实际请求体 HMAC，且推理次数必须等于业务请求数。

RSS 在模型 SDK 的鉴权 fetch 调用处采样，每个推理进程取发送时样本的最大值后相加。它不是峰值、同时刻全机内存或长期驻留曲线。Node CPU 是测量进程的 CPU 时间，包含桥接、模拟上游和消费端，不包含 OpenCode 子进程 CPU；排除最终完整文本断言。

以下为每场景一次冷启动样本，CPU 和耗时受系统调度影响，不作为稳定吞吐保证。所有推理使用虚构凭证和回环服务，不替代内网证书签名及真实供应商验收。

已经显式共享的单模型场景，RSS 基本不变；收益主要来自 SSE 连接合并，事件字节量下降约 82%。多模型场景同时减少进程副本，RSS 下降约 75%。

默认 4 路场景的 SSE 字节量增加约 60%～70%：全局流包含目录封装及生命周期元数据，且每个进程的启动事件占比更高。该场景的收益是减少进程，不能声称所有负载的事件字节量都降低。

## 正确性验证

- 90 项单元测试通过，覆盖队列上限、取消、共享流断开、独立错误与配置分组。
- OpenCode 1.16.2 和 1.18.0 各 9 项真实运行时集成测试通过，覆盖流式、工具往返、历史、参数、中断、超时、调用方重试和请求隔离。
- 两个版本的 64 路同合约测试均为 1 个推理进程，清理后 Session 数为 0。
- 16 路跨模型 / 供应商测试核对凭证、Cookie、实际请求体签名、采样参数及 Unicode 输出。相同模型列表下更新 provider 配置后，新请求使用新进程；刷新期间的旧请求正常结束。
- 不同工具 schema 使用不同进程组；结束后事件订阅数、排队字节、活动请求和控制器均为 0。

这不等同于长期内存稳定性证明。OpenCode 自身的运行时、数据库与 SDK 仍有固定成本。

## 复现

PowerShell 中设置真实程序命令，例如：

```powershell
$env:TEST_OPENCODE_COMMAND='["opencode"]'
npm run benchmark:resources -- --baseline artifacts/resources-before.json
npm run benchmark:resources -- artifacts/resources-after.json
```

按顺序运行，不与集成测试或其他压力测试并行。基线脚本只把固定提交的桥接源码复制到已忽略的 `bridge-runtime/resource-baseline`，不切换分支。原始 JSON 输出保存在本地 `artifacts`，不包含生产配置或凭证。

## 开源参考

- [Dheerax/opencode_mcp 的 server-manager.ts](https://github.com/Dheerax/opencode_mcp/blob/main/src/server-manager.ts)：借鉴持久 `opencode serve` 进程复用与健康检查的思路。
- [Dheerax/opencode_mcp 的 opencode-client.ts](https://github.com/Dheerax/opencode_mcp/blob/main/src/opencode-client.ts)：借鉴单条 SSE 配合多个监听者的事件分发方式。其 API 路径与本项目支持的版本不同，未直接移植接口。
- [chryzxc/vscode-opencode 的 MessageStreamService.ts](https://github.com/chryzxc/vscode-opencode/blob/main/src/services/MessageStreamService.ts)：借鉴集中管理事件流和订阅者生命周期的方式。

本项目采用按 Session ID 的有界队列；共享流断开后向调用方报错，不自动重连并重放正在进行的推理。
