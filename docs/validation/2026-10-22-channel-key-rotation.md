## 调度与接口覆盖

- 同渠道轮询、跨模型会话绑定、不同客户端/渠道隔离、90 个并发新会话均匀分配。
- 滑动过期、请求完成后续期、并发长请求保护、闲置 LRU 淘汰、全活动容量限制。
- 凭证替换/停用、地址变更、普通保存后的状态保留、配置代际切换中的旧请求完成。
- 数字和日期 `Retry-After`、401 失效与手动恢复、403 不轮转、有限尝试、单 Key 限流
  仍返回 429 和正确冷却时间、缺失环境变量、实际重复凭证去重。
- 输出前切换，输出后故障不重放，中断释放绑定/Key 与网关并发配额，共享首输出超时预算。
- 三个客户端协议的普通/流式响应、HTTP 会话头、metadata 会话标识、模型发现与 CORS；
  Responses 存储续聊自动继承绑定，未知/冲突/过长会话标识拒绝。
- 管理接口本机鉴权、密钥不回显、空值保留、失效状态复位、配置边界与别名冲突。
  停用渠道不能通过单个模型的启用覆盖重新开放。

## 真实 OpenCode 与浏览器

三项新增原生集成通过本地模拟供应商和一次性全局配置运行：

1. 三个客户端协议 × JSON/SSE 的两工具调用与逆序工具结果续聊，以及无关会话、并发、
   过期重分配。逐次检查实际上游收到的凭证，全局认证和配置文件执行前后字节一致。
2. 真实上游 401/429 经 OpenCode 返回后换 Key，中断后释放绑定，再次调用恢复。
3. OpenAI Chat、OpenAI Responses、Anthropic 三种上游 SDK 的真实 OpenCode 调用，检查
   上游路径、Bearer / `x-api-key` 凭证及普通/流式输出。

浏览器连接独立临时管理实例，验证空表单错误、新建双 Key 渠道、修改滑动期限、密钥留空保存、
未保存提示与取消、启停渠道、环境变量来源切换及缺失状态显示。测试实例已关闭，不更改生产配置。

并行验证曾遇到本机 Node 进程内存不足，改为顺序运行后相关单元和 SDK 测试均通过；Windows
临时目录清理出现短暂 `ENOTEMPTY`，测试夹具加入有限清理重试后 `npm test` 全部通过。

## 验证边界

没有使用生产 Key 或真实付费模型调用，没有测量实际供应商缓存命中率或多账号限额。
粘性绑定减少不必要的换 Key，但缓存是否共享仍由实际上游决定。绑定与健康状态为内存数据，
进程重启后清空；渠道初始请求仍可能冷启动，原有全局模型启动预热不替渠道推理。
